# DMRCheatSheet

Greg's project for his **Baofeng DM-32UV** radio: the W7AW club codeplug, and printable PDF
documents for **West Seattle Amateur Radio Club (W7AW)** members. The 5-page **Reference Sheet**
is built from the codeplug. A **Getting Started** sheet is being planned (`GETTING-STARTED-PLAN.md`).
The readers are mostly older hams, so **legibility comes first**. Keep text large
(about 11 pt minimum in tables and 13 pt or more for body text) and never shrink fonts to make content fit.
Split or trim the content instead.

## Repository

Git repo, remote `origin` = <https://github.com/gregorywright/W7AW-DMR> (**public**). Generated `build/` files, `__pycache__`
and the Baofeng manual are ignored. Don't commit anything private: the repo is public.

## Open questions / caveats

- **Zone 8 BEARS W.Tiger** is on 442.075 in the codeplug and in SeattleDMR's CSV, but
  SeattleDMR.org's web page lists Seattle East at 440.3375. The sheet shows the codeplug value.
- **V71 Lynwood** decoded as DCS 172. It's the only DCS tone seen. Confirm it in the CPS.
- **U11N West Sea** is on the same frequency as U11 but uses tone 123.0. Its purpose is unknown, so ask Tom.
- **Screen icons, confirmed 2026-11-26 from Greg's photos** (details in GETTING-STARTED-PLAN.md §5): **N** = narrowband
  (it matches the codeplug bandwidth bit, channel byte `+0x19` bit 7: 0 = narrow); **|+|** = repeater/duplex (absent on simplex
  WX4); **CTC** = CTCSS; red ▶ = main band; on-screen **A/B** labels the red ⌂ key. DIG/ANA badge: red = idle,
  blue = receiving (Greg). The screen-wide bar next to A/B
  is a relative signal-strength meter that fills solid blue on receive (Greg). All screen items are now identified.
- Does P1 wrap from zone 102 back to zone 1? Not tested.
- **APRS (2026-11-24):** Greg's position doesn't show on the maps. In the decoded codeplug, all 2,473 channels
  have APRS report mode Off (channel byte `+0x1C` bits 3-2, per the spec). The APRS settings page (`0x5300`) has
  report channel = current channel, schedule byte `0x01` (30 s by the spec's derived scaling, unverified) and
  a placeholder fixed position. The DM-32UV sends APRS **only as DMR SMS**, not as FM AFSK (Baofeng Part 7).
  It needs a repeater or hotspot whose network gateways SMS to APRS-IS (BrandMeister: private call
  to 310999, M-SMS format plus a BrandMeister SelfCare setting). It is unknown whether SeattleDMR repeaters pass
  SMS/APRS. Ask Tom or SeattleDMR.
- The talkgroup descriptions ("Local", "BayNet", "Spare link") are short on purpose. Only the
  Link 1–6 description is sourced (SeattleDMR: spare TGs an admin can patch to other networks).

## Codeplug format notes (`.data`, reverse-engineered)

Worked out from this one file (firmware string `DM32.00.01.048` at 0x30). Treat it as
**read-only knowledge**. Never write a modified `.data` back to the radio from these tools.
Make edits in the Baofeng CPS.

- **Channels**: u16 count at `0x21000`. The first page's records start at `0x21010` (84 of them).
  Later records are 85 per 4 KiB page starting at `0x22000`. Each record is 48 bytes:
  - `+0` name (16 bytes, NUL-padded)
  - `+16` RX and `+20` TX frequency, 4-byte LE BCD in 10 Hz units (`00 75 09 44` = 440.97500)
  - `+24` byte 0 bit 4 set = digital
  - digital: `+29` (byte 5) low nibble = colour code, bit 4 = slot 2
  - analog: `+33` RX tone and `+35` TX tone, 2-byte LE BCD in 0.1 Hz (`13 14` = 141.3).
    `ffff` = none. A high nibble of 8 or more is assumed to mean DCS.
- **Zones**: 145-byte records, 28 per page. The first page starts at `0x11010`, then pages at
  `0x12000`, `0x13000` and `0x14000`. Each record: name 16 bytes, count 1 byte, then that many u16 channel numbers.
  After the 102nd zone the bytes are stale garbage. The decoder stops at the first
  non-printable name.
- **Talkgroups**: 24-byte records from `0x1c002`. Each record: name 16 bytes, a pad byte, then a 3-byte LE ID.
  Records with an `ff` first byte are deleted entries.
- **Radio settings** (spec block 0x04) are the page at `0x5000`. Key functions are bytes `+0x87..+0x8a`
  (SK1 short/long, SK2 short/long) and `+0x8d..+0x90` (P1, P2). Long-press time is `+0x93`.
  The enum is in `tools/decode.py`.
- The channel-to-talkgroup link was not decoded. The sheet takes the talkgroup from the
  channel name instead (`"Seattle 1 SWE"` &rarr; talkgroup `Seattle 1` + zone suffix `SWE`).
  SeattleDMR codeplugs follow this naming.
- Zone channel numbers match the radio's `Ch` numbers within the zone (position 1-based).

## Radio / programming setup (for reference)

- The CPS runs in **Windows 11 ARM under Parallels** on Greg's MacBook Pro. In Parallels, use Devices &rarr;
  USB &amp; Bluetooth to give the cable to Windows.
- The cable has a **WCH CH340** chip (USB VID 0x1A86, PID 0x7523) and uses WCH's ARM64 CH341SER driver.
  Windows shows it as `USB-SERIAL CH340 (COM4)`. The Mac sees it as `/dev/cu.usbserial-*`.
- The CPS port speed is **115200 baud**. **Turn the radio on first, then plug in the cable.** With the
  cable already plugged in, the radio powers up to a blank screen.
- Windows shows a "compatibility settings" popup when the CPS starts. Answer "Run using compatibility settings".
- Greg's factory backup read was saved on the Windows side. Its location isn't recorded here.
- Greg's DMR ID and callsign are in CPS &rarr; Digital &rarr; DMR ID, row 1. The parrot test
  on Zone 11 Ch 15 worked on 2026-11-24.

**Rule: every statement on the sheet must trace to the decoded codeplug, the manual
(`docs/Baofeng_DM-32UV_User_Manual_20250210.pdf`, text in `docs/manual.txt`), an official
Baofeng guide, or a club/SeattleDMR page.** Mark anything else as unverified, or leave it off the sheet.

| Long press = hold 3 s | Codeplug `0x5093` = 2 (spec: stored 0-4 &rarr; 1-5 s). Baofeng Part 6 also says the default is 3 s. This is probably why "long press doesn't work": a normal ~1 s press counts as a short press. |

  match the club repeater page ([w7aw.org/echolink-irlp](https://w7aw.org/echolink-irlp/)):
  1. PTT and press keys `1` `2`, then wait for the repeater to say "Ready".
  2. PTT and say a test message ("Parrot Commo Check" + call sign).

  Label the two methods clearly so nobody tries "12" on DMR.
